# native/ — TfmEngine JSI host module

Part of the [ISOCUBE project](../../README.md). A hand-written JSI host module
that runs the same C++ transformer engine the backend uses (`../cpp`), embedded
entirely in the app binary:

- `TfmEngineRegistration.mm` — iOS global registrar that hooks `TfmEngine` into
  the TurboModule map (add this file to the Xcode target after `expo prebuild`).
- `include/tfm_model_data.h` — the weights file (`../cpp/model.bin`, 428235
  bytes) embedded as a C array. Generated by `scripts/embed_weights.py`; never
  commit a stale copy — rerun the script after exporting new weights.
- `include/tfm_memory_loader.hpp` — in-memory TFM1 parser. `tfm::loadWeights()`
  reads from a filesystem path; mobile forbids runtime file I/O, so this parses
  the identical binary format from the embedded bytes. Verified bit-for-bit
  against the golden fixtures (`cpp/tests/parity.cpp` tolerances).
- `cpp/TfmEngine.{h,cpp}` — the JSI layer:
  - `installTfmEngine(runtime)` installs `globalThis.__TfmEngine`, a
    `jsi::HostObject` with `load()`, `evalPosition(board, mask, n)`, `numel()`.
  - `TfmEngineTurboModule` (C++ TurboModule) whose `installJSIBindingsWithRuntime`
    installs that global. The JS side requests it through
    `globalThis.__turboModuleProxy('TfmEngine')` (see `src/native/TfmEngine.ts`).
- `TfmEngine.podspec` — iOS: compiles `../cpp/src/*.cpp` + `cpp/TfmEngine.cpp`
  into the app.
- `CMakeLists.txt` — Android: same sources as a static library `tfm_engine`,
  linked into `libappmodules.so`.

No runtime file I/O anywhere: weights come from the embedded header; the model
parses them from memory at first `load()`.

## Build wiring

### Android (automatic via `plugins/withTfmEngine.js`)

During `expo prebuild` the plugin:

1. Writes `android/app/src/main/jni/CMakeLists.txt` (the documented "customize
   the default app CMake" pattern) which includes RN's
   `ReactNative-application.cmake`, adds our `native/CMakeLists.txt` via
   `add_subdirectory(${PROJECT_ROOT_DIR}/../native ...)` and links `tfm_engine`
   into `libappmodules`.
2. Writes `android/app/src/main/jni/OnLoad.cpp` — a copy of RN's default
   OnLoad that additionally registers `TfmEngineTurboModule` in
   `cxxModuleProvider`, so `__turboModuleProxy('TfmEngine')` resolves it.
3. Patches `android/app/build.gradle` to point `externalNativeBuild` at
   `src/main/jni/CMakeLists.txt`.
4. Adds `REACT_NATIVE_VERSION` / `REACT_NATIVE_SO_NAMES` to `gradle.properties`
   (best effort; harmless).

Both files are written only if absent; the build.gradle/Podfile patches are
idempotent, so re-running `expo prebuild` is safe.

**Manual fallback** (if a future RN/Expo changes the CMake layout): after
`npx expo prebuild`:

```
mkdir -p android/app/src/main/jni
cp node_modules/react-native/ReactAndroid/cmake-utils/default-app-setup/OnLoad.cpp android/app/src/main/jni/
# edit android/app/src/main/jni/CMakeLists.txt to add:
#   add_subdirectory(${PROJECT_ROOT_DIR}/../native native_tfm_engine)
#   target_link_libraries(appmodules tfm_engine)
# and edit OnLoad.cpp cxxModuleProvider to return
#   std::make_shared<tfmengine::TfmEngineTurboModule>(jsInvoker)
# for name == "TfmEngine" (see the OnLoad.cpp template in plugins/withTfmEngine.js).
# Then in android/app/build.gradle android { } block add:
#   externalNativeBuild { cmake { path "src/main/jni/CMakeLists.txt" } }
```

Then build with Android Studio or `npx expo run:android` (Android SDK + NDK
required, see below).

### iOS (automatic Podfile patch + one registration file)

The plugin injects `pod 'TfmEngine', :path => '../native'` into
`ios/Podfile`. `pod install` then compiles `native/TfmEngine.podspec`
(depends on `React-Core`, `ReactCommon`, `React-jsi`, `React-callinvoker`).

**Registration (one manual step after `expo prebuild`):** the engine is
registered by a small global registrar — `native/TfmEngineRegistration.mm` —
that hooks the C++ TurboModule into the global module map, so
`globalThis.__turboModuleProxy('TfmEngine')` resolves to it. No AppDelegate
changes are needed.

After `npx expo prebuild`:

1. Add `mobile-rn/native/TfmEngineRegistration.mm` to the `ISOCUBE` target in
   Xcode (File ▸ Add Files, or drag it into the project navigator and tick the
   target). It compiles into the app and registers `TfmEngine` on startup.

The registrar itself:

```objc
#include <ReactCommon/CallInvoker.h>
#include <react/nativemodule/core/ReactCommon/CxxTurboModuleUtils.h>
#include <TfmEngine.h>

namespace {
struct TfmEngineRegistrar {
  TfmEngineRegistrar() {
    facebook::react::registerCxxModuleToGlobalModuleMap(
        tfmengine::TfmEngineTurboModule::kModuleName,
        [](std::shared_ptr<facebook::react::CallInvoker> jsInvoker) {
          return std::make_shared<tfmengine::TfmEngineTurboModule>(
              std::move(jsInvoker));
        });
  }
};
TfmEngineRegistrar g_tfmEngineRegistrar;
}  // namespace
```

> **Legacy alternative** (pre-RN-0.86 / bridge apps): override the factory
> delegate's `getTurboModule:jsInvoker:` in a `.mm` file instead — see the
> "ReactNativeDelegate.mm" pattern in older versions of this file. The global
> registrar above is the current, simpler approach.

Then build with Xcode or `npx expo run:ios`.

## Building

```
# regenerate the embedded weights header after exporting new weights
npm run embed

# Android / iOS
npx expo prebuild          # runs withTfmEngine; writes android/ + ios/
npx expo run:android       # or open android/ in Android Studio and Run
npx expo run:ios           # or open ios/ in Xcode and Run
```

### Requirements (a real machine)

- **Android**: Android SDK + NDK (the ReactApp Gradle plugin sets
  `externalNativeBuild`; `ndkVersion` comes from the project). CMake + C++20
  toolchain via AGP. `local.properties` with `sdk.dir` as usual.
- **iOS**: macOS + Xcode + CocoaPods (`pod install` runs automatically via
  `expo run:ios`).

### Sanity checks

`numel()` returns `106690` (matches `cpp/build/tfm-cli`'s `params=`), and
`load()` must return `true` before `evalPosition` is used.

## Verifying the engine + embedded weights (offline)

`cpp/` ships golden fixtures. A throwaway harness that loads the embedded bytes
through `tfm::loadWeightsFromMemory` (the exact production code path) and
compares against `cpp/fixtures/fixture_*_*.bin` passes with max |d| ≈ 3e-6
(far inside the 1e-3 CI tolerance). Rebuild it anytime with:

```
g++ -std=c++17 -O2 -I cpp/include -I native/include \
  /tmp/opencode/tfmtest/main.cpp cpp/src/{ops,layers,model,weights}.cpp -o memtest
./memtest cpp/fixtures   # expect MEMTEST: PASS
```
